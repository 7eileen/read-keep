# 登录与跨设备存储

## 目标与现状

当前 app.js 用 read-and-keep-demo-v1 将整个 state 保存到 localStorage。文章解析、词条、词典结果与回顾设置均在浏览器中；没有账号或后端。此次保留已有功能，增加邮箱密码登录及按用户保存、读取、修改和删除数据。

## 数据与权限

- Supabase Auth 管理账号、密码与会话，前端使用官方 SDK。
- articles：文章标题、正文段落、页码、版本及原有属性。
- entries：单词、文章来源、原句、译文、词典结果、收藏、笔记、回顾日期和次数。
- preferences：回顾间隔、每批数量、自动翻译开关。
- 三表均有 owner_id、id、payload JSONB、version、updated_at；(owner_id,id) 主键保留现有客户端 ID，支持重复迁移去重。
- RLS 对 authenticated 的 SELECT/INSERT/UPDATE/DELETE 均检查 auth.uid() = owner_id；匿名无表权限。不能改 owner_id。文章删除仍保留原有词条语境，故不将 entries 强制级联删除。
- 所有批量保存通过 SECURITY INVOKER RPC 在一个事务中执行，校验预期版本；版本冲突回滚整批，不覆盖他人或另一设备的较新写入。

## 同步与迁移

保留访客模式。登录只读取该账号的云端数据，不自动把当前浏览器的访客数据上传给任意登录账号。用户点击迁移后，按 ID 合并非演示记录；相同内容去重，ID 冲突提示。

本机按用户 ID 分开保存同步缓存和待提交变更；退出清理该账号缓存并取消进行中的翻译，恢复访客空间。待同步内容退出前需完成同步或导出后明确处理。账号切换清除草稿、弹窗、选区和回顾会话。会话失效时隐藏账号内容，未完成队列仅在该账号再次认证后恢复。

采用基线、本地、云端三方合并。不同记录的变更自动合并；同一记录同时改变或一端删除一端编辑，暂停提交并提示选择本机或云端冲突版本。保存过程中继续编辑不会被网络返回覆盖。同步在保存、恢复联网、回到页面和手动刷新时触发；不承诺逐字符实时协作。

## 部署

继续静态托管在 Netlify。构建先运行测试，再打包固定版本的 Supabase SDK，并生成公开配置。后台仅需 SUPABASE_URL 与 SUPABASE_PUBLISHABLE_KEY，绝不放入管理员 secret/service_role 密钥。SQL 在 Supabase 执行；邮箱验证保持启用，公众注册前需自定义 SMTP。

## 实施与验证顺序

1. 先写三方合并、迁移、保存中编辑、账号切换与失败重试测试，再实现独立同步模块。
2. 建表、RLS、版本校验和事务 RPC；集成官方认证 SDK、登录及账号控制界面。
3. 将现有 persist 接到按账号分隔的本地队列，修复文章写入失败仍报成功的问题。
4. 构建与后台配置说明；保持现有七组测试通过。
5. 两个专用测试账号真实验证 CRUD、跨客户端读取、越权 SELECT/INSERT/UPDATE/DELETE、退出切换与冲突；清理测试数据。
6. 浏览器检查桌面和手机布局、唯一关闭入口、同步状态，最后通过现有 Git/Netlify 流程发布。

此实施范围已由用户明确要求。采用当前任务中直接实现和验证的执行方式。
